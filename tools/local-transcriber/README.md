# Cockpit 端末内文字起こし — 精密モード限定・Intel Mac版

対象: Intel MacBook Pro 2019 / Core i9 / 32GB。CPUで実行します。音声・動画は外部の認識サービスに送りません。

## 初回準備・更新

1. ZIPを新しい書き込み可能なフォルダーへ展開してください。以前のツールや書き出し結果を削除する必要はありません。
2. `Setup.command` を実行します。専用Python 3.11、固定依存パッケージ、精密モデル（Whisper medium、約1.5GB）を取得します。準備時はインターネット接続が必要です。
3. 「モデル準備完了」と表示されたら利用できます。以前精密モデルを準備した端末では同じモデル保存先を再利用します。

標準モード・smallモデルの選択肢はありません。旧 `Setup-Accurate.command` も同じ初回準備を呼ぶ互換用入口です。旧smallモデルが保存済みでも使用しません。

モデル: `~/Library/Application Support/CockpitLocalTranscriber/model-medium`
専用環境: 展開フォルダー内の `.venv` / `.python` / `.tools` / `.cache`。初回準備後にフォルダーを移した場合はSetup.commandを再実行してください。
セットアップは固定版uvのSHA-256を照合し、専用環境のみを作成します。Homebrewや管理者権限は不要です。署名済みmacOSアプリではないため、macOSに拒否された場合は表示内容を確認してください。

## Cockpitから自動で文字起こし

1. 初回準備後、`Connect-Cockpit.command` を開きます。
2. 表示された接続キーを、Cockpitの対象案件 → 面談の録画・録音の接続キー欄に貼り付け、「端末内ツールに接続」を押します。キーは起動ごとに変わり、Cockpitには保存・同期しません。
3. Chromeでローカル接続の許可を求められたら許可してください。
4. 録音・録画ファイルをCockpitに入れます。動画は最初の音声トラックを `extracted-audio.wav`（16kHz・モノラル）に抽出して精密認識。音声ファイルは抽出ファイルを作る工程を省いて認識します。発言の省略・短縮はしません。
5. 完了すると元の録音に「精密文字起こし・要確認」として文章が保存されます。原文・時間区間も保持します。接続先は同じ端末の127.0.0.1:8765のみです。元動画・音声をクラウドには送りません。文章は案件データとして暗号化保存・同期します。
6. 結果は `~/Documents/CockpitTranscripts/cockpit-job-.../transcription-...` にも保存します。動画から抽出したWAVはここで利用できます。転送した入力の一時コピーは処理終了時に削除します。
7. 原音と照合・修正する場合は同フォルダーの `review.html` を開き、下記の確認済みJSON取り込みを使います。案件の予算・期限などは自動で書き換えません。

接続ツールを起動したMacのブラウザーで利用します。別のスマートフォンからMacのツールへは接続しません。初回モデル取得後は認識処理にインターネット接続は不要です。処理中はターミナルとCockpitの案件画面を開いておいてください。画面の移動・施錠・中止で処理を止めます。ブラウザーの強制終了・転送直後の切断では補助ツール側が続行する場合があります。その場合はControl+Cで止められ、保存済み結果は残ります。途中からの再開は未対応です。
接続できない場合は起動状態・キー・ブラウザーのサイト権限を確認してください。手動の処理・取り込みも利用できます。

## 手動で録音から案件に取り込むまで

1. `Transcribe.command` を実行し、録音・録画、保存先、人名・社名・専門用語（任意）を指定します。
2. 完了後、保存先の `transcription-.../review.html` をブラウザーで開きます。
3. 元の録音ファイルを選択し、各区間を再生して認識文を確認・修正します。元の認識文は保持されます。
4. 各区間の「原音・内容を確認しました」にチェックし、`確認済みJSONを書き出す` を押します。編集すると該当区間のチェックが外れます。
5. Cockpitの対象案件 → 面談の録画・録音で録音を登録し、該当録音の `精密文字起こしを取り込む` から `cockpit-reviewed.json` を選びます。
6. 対象案件・録音との対応を確認して取り込みます。原文・修正文・時間・精密モデル情報が案件データに保存されます。
7. 「設問の下書きを作る」で内容を利用できます。予算・期限・決定事項は自動で確定・上書きしません。



補助ツールの確認途中の編集は自動保存されません。ブラウザーを閉じる前に書き出してください。すべての区間を確認するまではJSON/TXTの出力はできません。今回のJSON形式はversion 2で、精密モデルの情報を含みます。旧版JSONは新しい補助ツールで処理・書き出し直してください。

## 保存と中断

- `transcript.txt`: 認識した原文。
- `segments.jsonl`: 時間と原文。
- `review.html`: 原音再生・編集・確認用の画面。
- `status.json`: 処理状態、モデル、録音名、処理時間。
- Control+Cで停止。保存済みの区間は残ります。中断位置からの再開は未対応です。
- これらは**平文ファイル**です。Cockpitに取り込んだ後の暗号化保存とは別です。他人に公開しない保存先を選択してください。
- 初回準備後はオフラインで実行できます。Macのスリープを抑止しますが、ふたを閉じた状態・強制終了での継続は保証しません。

## 文脈補正（任意の実験機能）

`suggest.py` はローカルのllama.cppとGGUF文章モデルを指定して、最大10区間ずつ補正候補を作ります。Mac向けの文章モデル自動セットアップは含めていません。標準の精密文字起こし・Cockpit取り込みに、この機能は必須ではありません。

```sh
.venv/bin/python suggest.py --result /path/to/transcription-folder --llama-cli /path/to/llama-cli --model /path/to/Qwen3-4B-Q4_K_M.gguf --start 0 --limit 10
```

Qwen3-4B Q4_K_Mの少数例で有効な修正候補が出ましたが、金額・社名の誤変更も発生しました。数値保護、原文一致、明示された固有名詞の検査で候補を除外しますが、意味の正しさを保証する検査ではありません。候補は自動適用せず、原音を聞いて採用します。

## 制限・検証範囲

入力上限は3時間・4GiBです。全音声を16kHz monoに変換してメモリに保持します。1〜3時間の実会議の連続試験は未完了です。最初の音声トラックのみ認識し、話者分離・声とBGMの分離はしません。
数字・人名・否定・決定事項を原音で確認してください。精密モデルでも誤認識や発言の補完があり得ます。無音による発話スキップを無効にしているため、長い無音では不要な文章が出る可能性があります。
Linuxで固定依存版の実音声処理、確認画面、CockpitへのJSON取り込み・暗号化保存・再読み込みを検証しています。Intel Mac実機の速度・発熱、macOSダイアログは未検証です。

faster-whisper 1.2.1 / CTranslate2 4.3.1 / CPU int8 / 4スレッド。
精密モデル: Systran/faster-whisper-medium、revision `08e178d48790749d25932bbc082711ddcfdfbc4f`。
推論は `HF_HUB_OFFLINE=1`、`local_files_only=True`。モデル未準備時に標準モデルへ切り替えることはありません。

## 削除

展開フォルダーと上記モデルフォルダーを削除するとツールを取り除けます。書き出したファイル、旧smallモデル、Cockpitの案件データは残ります。

実行前に固定の精密モデルのSHA-256を照合し、別モデルや破損したモデルを拒否します。照合にはディスク読み込み時間が加わります。
