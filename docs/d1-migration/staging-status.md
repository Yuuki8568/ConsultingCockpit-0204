# D1移行の実装状況

この変更はレビュー用の途中段階であり、本番へのマージ・公開はまだ行わない。

## 確認済み

- Cloudflare D1 `consulting-cockpit-db` に移行候補の保存用テーブルを作成。
- クライアントで暗号化済みの値を復号せずコピーし、読み戻した値のSHA-256と件数を照合する。
- MiniflareによるD1実行テストで、保存照合、連続実行制限、所有者の分離、入力上限、書込失敗時の未完了扱いを確認。
- フロントエンド・APIの型検査、フロントエンドビルドを確認。
- ユーザー確認済みのバックアップ・復元試験は繰り返さない。

## 公開前の必須事項

- 全消去、鍵変更、並行する移行コピーを含めた移行候補のライフサイクルを整合させる。現段階では既存の全消去APIがD1コピーを削除しないため、公開不可。
- libSQLの対話型トランザクションを、D1のバッチ・条件付き更新で同等の整合性を保つ設計へ変更し、競合・鍵更新・端末失効を検証。
- 認証情報を含めた本切替の対象・手順を確定。現候補コピーにはOAuth・セッション等を含めない。
- 利用者の認証済みセッションで実データをコピーし照合。まだ実データはコピーしていない。
- 書込み停止期間中の最終差分、一致確認、切替、戻し方を確定。
- 契約書・説明文は実際の切替完了後の構成に一致させる。既存の締結済み書面を上書きしない。

現在の正本は既存のlibSQL接続先のまま。D1は検証用の受け皿であり、D1移行完了とは記載しない。
