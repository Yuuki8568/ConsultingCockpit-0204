# 端末内文字起こし（本番未反映）

録音・録画の取り込み後、日本語をブラウザのWeb Workerで自動認識する。
取り込み時のチェックを外せば従来通り保存だけ行える。既存の未文字起こしファイルもボタンで実行可能。
音声・動画・PCMはサーバーへ送らない。認識文章は既存の案件内に保存され、既存の暗号化同期・バックアップ対象になる。
動画の音声トラックを認識する。話者分離・BGM除去・音声だけのファイル書き出しは含まない。

## 実装と制限

- Transformers.js 3.8.1、onnx-community/whisper-tinyの固定リビジョン、q8、WASM単一スレッド。
- 初回はHugging Faceから約44MBのモデル関連ファイルをGETし、ブラウザのモデルキャッシュを利用。
- WASMと実行用JSは自サイトで配信（WASM約21.6MB）。外部への認証情報送信なし。
- 64MB以下、再生時間を判定できる10分以内のメディア。ブラウザが音声をデコードできないコーデックはエラー。
- 日本語専用設定。軽量モデルのため固有名詞・雑音・長い無音等に弱く、結果は必ず人が確認する。
- 中止、案件変更、ロック、画面離脱で認識Workerを終了する。手動編集・削除を遅れて届いた結果で上書きしない。
- 30分の処理タイムアウト。短いファイルで再試行可能。モデルはキャッシュされるが完全オフラインでの初回利用は不可。
- Cloudflareの既存Workerで本番URLを運用しているため、feat/local-transcriptionで開発。自動デプロイ対象ブランチは変更しない。

## 検証

型チェック（app/node）、Vite本番ビルド、既存セキュリティ/Cloudflareと追加文字起こしテスト21件が成功。
Chromiumの実Worker、実WASM、実量子化モデルで、公開されている日本語サンプルの最初の12秒から日本語文章を生成した。
モデル配布元へのブラウザ直接通信は実行環境で失敗したため、同じ固定版のモデルを事前取得し、Playwrightで配布リクエストに応答した。
これはエンジンの実動作確認であり、実運用回線のダウンロード・Google Access経由の配信・スマホ性能の確認は未完了。
日本語サンプル: https://huggingface.co/kotoba-tech/kotoba-whisper-v2.2/tree/main/sample_audio
録音内容に対する正解率の評価は行っていない。

再現用（packages/webから、ビルド後）:

```sh
TRANSCRIPTION_FIXTURE=/absolute/path/short-japanese.wav node scripts/test-local-transcription.cjs
```

制約のある試験環境ではTRANSCRIPTION_MODEL_DIRに固定版モデルの保存ディレクトリを指定できる。
テストは実アカウント・実DBを使わない。認識文字列はログに出さず長さのみ表示する。

## 本番反映前の受け入れ確認

1. 別の保護されたプレビュー環境で、短い日本語MP3/WAVと音声付きMP4を取り込む。
2. モデル取得、進捗、中止、再試行、文章保存、手動修正を確認する。
3. 認識途中に案件変更・ロック・削除を行い、文章が誤った案件へ保存されないことを確認する。
4. 64MB/10分超過、音声なし動画、非対応コーデックの案内と元ファイル保持を確認する。
5. PCとスマホで処理時間・メモリを確認する。別端末には文章のみ同期されることを確認する。
6. Networkで外部送信がモデルGETだけであること、ローカルWASM配信でAccess認証が通ることを確認する。
7. 上記の確認後にデプロイ対象ブランチへ反映する。DBマイグレーションやシークレット追加は不要。
