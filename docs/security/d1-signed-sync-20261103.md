# D1本移行：署名付き同期・鍵変更の実装（2026-11-03）

> 2026-11-03時点の開発経緯です。配線・実機確認を含む現状は[11月6日の残件再点検](remaining-work-20261106.md)を参照してください。後段の未完成・未確認という記述を現時点に適用しないでください。

この変更は移行候補であり、本番Workerの保存先・バインディング・実データは変更しない。

## 実装

- 現行のDrizzle定義から認証、金庫、レコード、履歴、署名鍵、端末、監査、制限カウンターを含むD1用初期スキーマを生成。既存DBには適用しない。空の検証用ターゲット専用。
- 同期と鍵変更の入力検証定義を共通化。既存libSQL経路の入力仕様は維持。
- D1同期処理は、一貫した読取バッチから計画を作り、署名・チャレンジを確認した後、一回の書込バッチで確定する。
- 確定時にセッション期限、端末失効・セッション結合、鍵世代、署名鍵版、レコード件数と最大seqを再確認。初回検証直後の失効・同時更新も拒否する。
- チャレンジ消費、上書き前の暗号文と旧KDFの保全、レコード更新、監査と末尾更新を一括処理。書込失敗時に全体を取り消す。署名なしの代替経路はない。
- 送信量・件数・頻度の制限カウンターは業務更新とは別に確定し、拒否時もカウントを保持する。
- D1鍵変更では操作対象に結び付いた一回限りの本人確認を消費し、全対象のbaseSeq・件数を確認。暗号文、署名秘密鍵の暗号化包み、KDF、世代、監査を一括変更する。
- 応答紛失後の鍵変更再試行は新しい本人確認が必要。同じ本人確認の再使用は拒否する。

## 検証済み（架空データ・ローカルD1）

- 新規保存、暗号文そのままの読み戻し、署名なし拒否、署名後の改変拒否、再送拒否。
- 同時更新は片方だけ採用。古い版は競合として返す。敗者による履歴・監査の残存なし。
- 監査保存の後半で故意に制約違反を起こしても、暗号文・履歴・チャレンジ消費が全て元に戻る。
- 別利用者、失効端末、検証後から確定直前までの端末失効、古い鍵世代を拒否。
- 鍵変更の本人確認なし・古いbaseSeq・本人確認再使用を拒否。
- 鍵変更時の監査失敗で暗号文・署名鍵世代・金庫世代・本人確認消費が元に戻る。
- 鍵変更の読取後に別の更新が入ると拒否。正常変更と新しい本人確認による同内容再試行は成功。

## 現段階の制限

- D1実装は本番ルーターから呼ばれない。認証・パスキー・端末管理・金庫管理の候補実装とローカル結合試験を追加したが、D1用HTTPルーター・監査照合・外部監査送信の実装とローカルHTTP結合試験は追加済み。本番Workerへの接続と実データ移行経路は未完成。Google OAuthの実際のリダイレクトとMac/Androidの実機パスキーは未検証。
- 同期の検証用スナップショットは1000レコード、暗号文総量16MiBまで。SQL側のサイズ条件で大きな結果を先に抑制し、不一致時は拒否する。HTTP相当の入力上限は4MiB。大きい金庫はページング設計の拡張が必要であり、制限を無視して切り替えない。
- 本番へ移行する前に、全テーブルの整合したコピーと読み戻し照合、認証・端末制御・正常同期の結合試験が必要。
- 所有者確認済みの実データ復元試験は再実施していない。実データの取得・コピー・変更もしていない。
- 契約文面はD1移行済みとして確定しない。Android実機確認も別途未完了。

## 追加実装：認証・端末・金庫（同日）

- Better Authの設定を共通化し、リクエスト単位のD1アダプターを作成。署名Cookie・セッション期限・所有者・メール確認・Origin・失効端末の判定を検証。既存libSQL経路のデフォルト設定は変更しない。
- D1端末登録は一回限りの操作別追加認証を要求。既存セッションの端末IDは変更不可。削除は失効記録として残し、復旧には別の追加認証が必要。他端末セッションの削除と監査を同じバッチで確定。100セッションを超える場合は安全側に拒否。
- 仮想Chromiumパスキーで登録→別経路承認→追加認証→署名鍵登録→チャレンジ→署名付き同期を確認。承認値の変更はテストプロセス内の架空鍵のみ。本番承認キーは変更しない。
- パスキーの検証失敗時にもチャレンジは消費。カウンター更新と操作別チケット発行は一括確定し、発行失敗時にカウンターだけ進まない。署名鍵登録は版・鍵世代とチケットを検証し、監査を一括確定。
- 解錠材料取得は永続カウンターと成功/拒否履歴を同じバッチで確定。履歴削除後も制限が継続。金庫全消去は業務テーブルだけを対象とし、制限・監査・ログイン履歴・セッション等を維持。全て架空データで検証。

追加試験：`node tests/d1-devices.cjs`、`node tests/d1-auth.cjs`、`node tests/d1-vault.cjs`、`node tests/d1-passkeys.cjs`（最後はPlaywright Chromiumが必要）。CIに組み込み済み。

### 独立監査証跡

D1用の独立監査保存先への送信処理も追加。既存と同じサービスバインディングのプロトコルを使用し、公開HTTPの送信先は追加しない。架空の保存先で正常な追記、同じ末尾の再送省略、既に保全された末尾の欠落、初回保全前の短い末尾欠落、IV改変の拒否を確認。監査照合はD1用HTTP APIで検証済み。実際のWorker/cronへの接続は未実施。

### HTTP結合試験

既存APIと同じoRPCの経路名・JSON形式でD1用Honoルーターを追加。実セッションCookieを使い、HTTP経由で仮想パスキー登録・追加認証・署名鍵登録・同期を実行。`sync/pullAll`、集計、端末一覧、履歴の記録/削除、監査追加/一覧/件数/独立証跡照合も検証。クライアント申告の時刻と端末IDは監査で採用しない。未認証・不正Origin・4MiB超入力・保守中の変更・監査切詰め・自動完全消去を拒否。実Google OAuth・実端末の操作ではない。

監査の全件照合は10000件/暗号化ペイロード16MiB、一覧ページと独立証跡送信ページも16MiBを上限とする。上限超過時に検査済みと表示しない。大規模履歴のストリーミング検査は別途必要。
