## コピー処理の保証範囲

- ソースはlibSQLの読取トランザクションで取得し、書き換えない。
- スキーマ定義にある18テーブルを対象とする。所有者、列名、件数・容量、外部キーを検査。
- 暗号文、IV、KDF、利用者ID、署名鍵の暗号化包み、パスキー、セッション、履歴・監査・制限を同じ値でコピー。復号しない。
- 空のターゲットに限って一回のD1バッチで挿入。確定直前に空であることを再確認し、並行した別の書込みも拒否する。
- コピー後に18テーブルを別途読み戻し、行数とSHA-256を照合する。戻り値は件数とハッシュのみ。
- ソース値・秘密値をログやファイルへ出力しない。ソースの接続情報は将来の実行Worker内で既存Secretsを参照する設計にする。
- この初版は全体2000行・JSON換算16MiB・1行1900000バイト、業務レコード1000行、セッション100行まで。超過時はコピー前に拒否する。実件数は未照合。
- 複製後の異常を検出したターゲットは未検証のまま隔離し、切替も自動消去もしない。既存ターゲットへの再実行は拒否する。

ハッシュ一致はコピーの一致を示す。元の記録が正しいこと、復号可能なこと、独立監査証跡との一致、本番Workerの正しい配線まで証明するものではない。

## 本番切替前に実装・確認するもの

1. D1バインディングを使用するWorker入口とcronの切替、未設定時の拒否、既存Access JWT・ホスト・Origin検査の維持。現在の本番WorkerはD1 APIを呼ばない。
2. 専用の移行実行Worker案をレビューし、既存Secretsを保持したままソースのAPI・認証・cronの書込みを止めて配備する。通常のCOCKPIT_READ_ONLYだけでは、解錠回数・認証更新等の書込みまで停止しないので不十分。
3. コピー先スキーマ、実件数・容量、ソースの監査と独立証跡の事前照合。実行Worker以外からターゲットへ書き込めないことを確認。
4. ソースを固定した状態でコピー・読み戻し照合し、データ本文やトークンを返さず結果だけ確認。
5. D1版を読取制限付きで接続し、Googleログイン、パスキー、既存データの復号・一覧・同期を実際の端末で確認した後、書込みを開く。所有者が確認済みのバックアップ復元試験は繰り返さない。
6. D1への最初の書込み前なら元のlibSQL経路へ戻せる。D1書込み開始後は元DBに差分がないため、コードだけを旧版へ戻してはならない。先に書込み停止と差分回収/照合が必要。署名なし旧版への切戻しは禁止。
7. 実態に合わせた保存先表示と契約管理票を確定する。切替完了日時と実際の適用版を記録する。

## 移行実行Worker案の停止条件

`cockpit_cutover_receipt` にrunningを一度だけ確保し、コピー・照合成功後にverifiedを記録する。verifiedは「コピーの一致」であり、cutoverは常にfalse。失敗はfailed、実行中断はrunningのままとし、自動再試行しない。認証トークン・秘密値は結果に含めない。必要な表の作成、既存Secretsの保持、移行対象D1バインディングと元の版に戻す配備手順を確認するまで本番へ置かない。
