# D1分割移行：独立照合と監査の工程記録（2026-11-17）

## 完了範囲

コピー時の記録、移行先の独立読戻し、元DBの再読込、監査連鎖・独立証跡の照合を内部部品として実装した。架空データによるローカル試験を行い、実データのコピー・D1切替・公開運用入口への接続は行っていない。確認した部品の公開・マージ・配備と、業務DBの本番移行は区別する。

本番用の実行管理、完全なスキーマ検査、全書込停止、実データ事前検査、無料枠での実CPU・利用量測定、契約・保存地域の確認は引き続き必要。以下の内部結果だけでは本番を切り替えられない。

## コピー時のv2記録

`d1-stream-digest.ts` はJSON配列をSHA-256に入力する固定形式 `cockpit-d1-stream-v2` を定義する。開始値には実行ID、スキーマ定義と対象範囲のハッシュを含める。1行ごとに前のハッシュ・表番号・値配列、表末尾では前のハッシュ・表番号・表件数・累計件数・累計JSONバイト数を含める。空の表も末尾記録に含める。

`d1-copy-checkpoint.ts` はコピー行と進捗に加えて、この累積ハッシュも同じ原子バッチで保存する。旧進捗ハッシュも更新条件に含める。v1の全配列ハッシュ・切替receiptとは互換性がなく、既存の有効化条件へ流用しない。

管理表の定義とスキーマ識別値を変更した。旧形式の途中進捗を自動変換・削除・再利用しない。実行する場合は、別の空の移行先と明示した準備手順が必要。今回、遠隔DBへ新管理表を作成していない。

## 独立した二つの照合

`d1-copy-verification.ts` はコピー完了時のハッシュ・件数・容量・実行ID・版を固定し、専用の進捗表に保存する。

1. **移行先読戻し**：D1の保存済みデータを改めて1行ずつ読む。コピー時の配列や書込応答を再利用しない。全18表で再計算したv2ハッシュ・件数・容量がコピー時と一致することを確認する。
2. **元DB再読込**：元DBを別の読取パスで再度1行ずつ読み、同じ三項目を確認する。移行後に元DBが変更された場合も不一致になる。
3. **独立証跡再確認**：利用者ごとに、監査末尾と別サービスの証跡が読戻し開始時から変化していないことを確認する。

1回の処理は1行、1表の終了、または1利用者の最後の証跡確認。進捗は旧全項目とコピー完了記録を条件に原子的に更新する。同時実行で確定できるのは1つだけ。再開時は主系から読み、応答だけ失われた場合も保存済み進捗を確認できる。行・主キー・利用者ID・証跡本文は戻り値へ含めない。

内容・型・監査等の不一致は `failed` を保存し、その実行を再開・再初期化しない。通信や結果不明を成功に置き換えず、同じ実行の進捗読戻しを要求する。自動再試行・自動消去は行わない。試行上限・期限・リース・日次残量の管理は別途必要。

## 監査の確認範囲

`d1-bounded-audit.ts` は移行先読戻し中に利用者別の監査末尾・件数と、独立した既存Witnessサービスの証跡を読み取る。監査イベントごとに、所有者、正の連番、前のイベントとのつながり、同じ番号の重複、既存v1/v2形式のハッシュ、保存末尾と証跡位置での一致を検査する。監査headだけが存在する、途中が欠落する、別の利用者を指す状態も拒否する。

Witnessは既存サービスのGETだけを使い、記録の更新・新規発行を行わない。応答の取得上限を4KiBとし、不正な値・通信失敗・証跡の欠落を合格へ読み替えない。証跡が監査全体より後ろにある場合や、最後の再確認で変化した場合も停止する。独立証跡が途中までの場合、証跡で固定されるのはその位置までであり、それ以降は連鎖検査で確認する。

`dataMatched` と `auditVerified` は部品の確認結果である。両方がtrueでも総合の `verified` と `cutoverAllowed` はfalseのままとし、既存の切替receiptは作成しない。

## 検証

ローカルlibSQLとMiniflare D1の架空18表・20行で、Nodeの別実装によるハッシュ照合、再起動後の再開、同時実行、応答喪失、バッチ末尾の失敗・全取消しを確認する。件数とバイト数が変わらない内容改変、元DBの後発変更、未対応型、コピー記録の差替えを拒否する。複数の監査イベントのつながり、監査本文の改変、前のハッシュの差替え、head不整合、独立証跡の不一致・後発変更・通信失敗・過大応答を個別に試験する。

既存の読取・コピー・一括移行試験を維持する。新しい定期実行、外部送信先、認証情報、依存関係、CIジョブ、料金設定は追加しない。変更ファイルに限定してGitleaksと手動差分確認を実施する。Semgrepは承認済みローカルルールがなく未実施。依存・スキル変更がないためOSV・Cisco開発検査は対象外。実サイトのZAP検査は行わない。リモート連携内部は未検証。

## 本番移行の判定

部品は外部の書込停止を証明しない。D1セッションの整合性は全表の固定スナップショットではなく、管理表も第三者の改ざんに対する独立した証明ではない。コピー前後を通じた書込停止、旧処理の終了、実際のソース接続と識別値の一致、完全なスキーマ・外部キー、運用上の停止・再開・失敗隔離、最終の切替記録とD1アダプターの受入れ検証が必要である。

無料枠のCPU内で動くことをローカル試験だけで保証しない。D1の地域ヒントも特定国での保存保証ではない。実際の契約・保存条件を確認するまで業務DBの移動は行わず、追加課金が必要なら変更前に金額と理由を説明する。
