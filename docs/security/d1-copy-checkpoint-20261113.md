# 無料枠D1移行：少量コピーと進捗保存の工程記録（2026-11-13）

## 完了範囲

`security-ops/d1-copy-checkpoint.ts` に、[少量読取](d1-bounded-reader-20261113.md)を使って1行ずつコピーし、その進捗を同じD1バッチで確定する内部用の部品を追加した。公開API・cron・本番入口には接続していない。ローカルの架空データでのみ動作確認した。

これは[無料枠の移行計画](d1-free-plan-20261110.md)の一工程であり、実行可能な本番移行ツールではない。実データの取得・コピー・移行先への管理表追加・切替は未実施。プラン、依存関係、認証情報、権限、通常のアプリ動作に変更はない。

## 原子的なコピーと再開

- 書込停止と移行先の切離しを呼出元に要求する。ただし真偽値は停止の証拠ではない。元DBの識別ハッシュも呼出元が実接続と照合する必要がある。
- 準備済みの別のD1で、18業務表・既存の移行管理表・切替記録・補助表・進捗表が空の場合だけ初期化する。既存行の削除や置換、業務表の自動作成は行わない。
- 進捗には実行ID、スキーマ定義と対象範囲のハッシュ、版番号、表番号、最終主キー、件数、JSONバイト数を保存する。認証情報は保存しない。主キーを含む進捗表は非公開の運用情報として扱う。
- 1呼出しで直後の1行または1表の終了だけを処理する。元DBは読取専用トランザクション。移行先の旧進捗全項目を条件に更新し、業務行の通常のINSERTと同じバッチに入れる。変更件数のCHECK違反でバッチ全体を取り消す。
- 進捗の読み取りは `withSession("first-primary")` から始める。古い版での実行は拒否し、並行して同じ版を処理した場合も確定できるのは1つだけである。
- 保存後に応答だけ失われる場合があるため、エラー時に自動再実行しない。同じ実行ID・対象範囲で保存済み進捗を読み直して判断する。初期化の応答不明でも別の実行IDでやり直さない。
- 既存の業務行を上書きしない。所有者、1行64KiBの保守的上限、合計2,000行・16MiB、record表1,000行・session表100行を検査する。これらは開発段階の制限であり、FreeのCPU・利用量を保証しない。
- 補助表のCHECK制約と進捗表の定義、対象業務表の列・主キー順を確認し、移行先のトリガーを拒否する。完全な型・索引・外部キー・制約・監査検証の代替ではない。
- 戻り値は集計と進捗状態のみ。例外本文を固定コードに置き換え、本文・主キー・メール・接続情報を外へ出さない。完了状態 `copied` でも `verified` と `cutoverAllowed` は常にfalse。既存の切替用receiptを生成しない。

バッチの全体取消しとセッションの整合性は[Cloudflare D1公式仕様](https://developers.cloudflare.com/d1/worker-api/d1-database/)を参照。ローカル試験の成功だけで、遠隔D1の全失敗状態を網羅したとは扱わない。

## 検証

`tests/d1-copy-checkpoint.cjs` は架空のlibSQLとMiniflare D1を使い、既存の移行試験入口から実行する。

- 18表・19行をコピーし、実行環境を終了・再起動して保存済み進捗から再開。別の照会で型と各値のバイトを全件比較し、NUL、日本語、絵文字、引用符の保持を確認。
- 同じ進捗の並行処理は1つだけ確定。古い版と対象範囲の変更を拒否。
- 保存成功後の応答喪失から進捗を読み直し、重複なしで再開。保存前・バッチ末尾の失敗で、データと進捗をともに未確定に保つ。
- 既存データ・旧切替記録がある移行先、弱められたCHECK、トリガー、所有者不一致、未確認の所有者、過大行、不正な進捗を拒否。
- 初期化後に別途挿入された同じ主キーを置換せず、進捗更新も取り消す。境界の進捗を注入した試験で、合計行数・バイト数と表別上限を超える次の1行を拒否。
- 完了後も切替記録を作成せず、本文を返さない。合成の秘密文字列を含む例外も固定コードで隠す。

変更ファイルに対するGitleaksと手動差分確認を実施する。Semgrepは承認済みローカルルールがなく未実施。依存変更がないためOSV、スキル変更がないためCiscoは対象なし。ZAPの実サイト検査は行わない。リモート連携の内部実装は未検証。

初回CIは型検査・D1試験・Webビルドまで成功したが、`ubuntu-latest` がUbuntu 26.04となり、固定済みPlaywrightがChromiumの導入を拒否した。既存の `security-release.yml` のverifyジョブだけをUbuntu 24.04に固定して再検証する。テスト削除、依存更新、権限追加、新しいジョブや外部送信の追加は行わない。[Playwrightの対応環境](https://playwright.dev/docs/intro#system-requirements)と[GitHubの公開リポジトリ用標準ランナー](https://docs.github.com/en/actions/reference/runners/github-hosted-runners)を確認した。標準Ubuntu 24.04は公開リポジトリで無料の対象である。

独立した読戻しと元DB再読込、分割ハッシュ形式、監査連鎖と独立証跡の照合、失敗隔離・リース・試行上限・日次残量管理、完全なスキーマ検査、全書込停止と旧処理終了の確認、実データ事前検査、FreeでのCPU・読み書き量の実測、契約・保存地域の確認、本人によるデータ確認が未完了。進捗表は独立照合や改ざん検出の証明ではない。

現用libSQLを維持し、これらを満たしてから本番移行を判断する。追加課金が必要になる場合は、変更前に金額と理由を説明する。
