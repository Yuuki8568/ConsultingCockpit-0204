## 今回の修正

1. **大きい監査記録で定期照合が進まなくなる問題**。D1では先頭1,000件の暗号化詳細が16MiBを超えると毎回停止し、libSQLは最大1,000件の本文を容量制限なしで読み込んでいた。先に最大1,001件の番号・ハッシュ・長さだけを読み、最大1,000件／推定2MiBの連続ページを選ぶ方式へ統一した。本文を読むSQLでも同じ容量条件を再確認し、件数・番号・ハッシュ・連鎖が変われば独立証跡を進めない。変更なしの回はDB照会2回、本文転送なし。変更がある回は本文照会が1回増える。5分間隔や独立保存先は変更しない。
2. **鍵変更の復旧中に別タブの行削除を見逃す問題**。新旧暗号文との値比較の前に、原本と現在のID集合・件数を照合する。消えた行や同じ件数での差し替えを検知したら、録画の仮チャンク採用前に停止し、復旧情報を残す。
3. **送れない鍵変更が復旧待ちとして残る問題**。実際に再暗号化した要求について、保存方式ごとの件数、1件の暗号文長、鍵情報を含むJSONのUTF-8バイト数を確認する。4MiBのHTTP上限に対して認証情報・RPC包み用に16KiBを確保する。超過時は復旧ジャーナルや仮メディアを保存する前に停止する。サーバー側の検査・一回限りの本人確認・原子的切替は維持する。
