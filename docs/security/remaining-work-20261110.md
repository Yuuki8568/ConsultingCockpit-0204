# 追加課金なしの残件対応（2026-11-10 JST）

本書は同期の復旧案内とバックアップ状態表示の追加改善を記録する。公開・反映日時と対象版は対応PRの最終状態を参照する。前回までの改修は[11月7日の記録](remaining-work-20261107.md)と[PR #19](https://github.com/Yuuki8568/ConsultingCockpit-0204/pull/19)を参照する。

## 同期エラーから通常の本人確認へ案内

ログインセッションと端末の結び付けが未完了の場合、同期は拒否される。画面のエラー表示から「取込・書き出し」の本人確認へ直接進めるようにし、再ログイン後も承認済みパスキーで確認する手順を示す。一般の通信・失効・権限エラーをすべて同じ原因と断定せず、元のエラーも表示する。

通常の本人確認と端末登録が成功し、金庫が解錠済みなら既存の同期処理を再試行する。再読み込みとパスフレーズの再入力を必須にしない。「本人確認完了」と「同期成功」は区別し、通信失敗を成功表示に変えない。認証中止・失敗時には端末登録も再同期も開始しない。

パスキー作成・管理者承認・失効端末の判定・サーバー側の認証条件・署名・鍵は変更しない。本人確認を自動承認せず、従来の確認を使う。バックアップ未設定の案内も設定の対象タブへ直接移動する。通常の設定入口は従来どおりプロフィールから開く。

## バックアップ状態表示の追加メモリを抑制

従来は、保存先や比較対象のバックアップがなくても編集のたびに金庫全体を複製し、照合用の値を計算していた。新しい編集で古い照合が不要になっても、計算自体は停止できず並行して複数の複製が残り得た。

保存先未設定・停止中・保存済みスナップショットなしの場合は照合用の複製を作らない。バックアップ表示の1つのマウントにつき実行中の照合を最大1件とし、待機中の作業は最新の編集に置き換える。待機時は金庫を複製せず、実際に照合を始める時点で複製する。古い版・施錠前の応答で新しい版を保存済みと表示しない。失敗後も待機中の最新確認を継続する。

暗号化バックアップのファイル形式・保存周期・復元検証・保存先・原本の扱いは変更しない。これは表示用の追加複製を抑える改善であり、金庫全体の段階復号ではない。照合が必要なときの1回分の全体複製・文字列化は残る。画面を閉じる直前に実行した計算そのものは中断できず、再マウントとの一時的な重なりまでは解消していない。

## 検証

- 型検査、Cloudflare向けビルドが成功。
- 独立したChromeの8MiB合成データで、未設定時の照合0回、12回の連続編集中も同時照合最大1件、待機作業が最新の編集のみになることを確認した。
- 古い照合の完了、照合失敗、施錠と遅延応答で、未保存・施錠状態を保存済みへ戻さないことを確認した。
- 実際の設定コンポーネントで、360・412・1280pxの画面から本人確認へ直接進む操作を確認。仮の認証中止は登録・同期0回。仮の本人確認成功後は同期を試し、同期の通信失敗を維持し、成功時は再読み込みなしで表示を更新した。
- 既存の暗号化バックアップ試験で、復元照合、編集時・保存中編集の未保存表示、原本不足・破損・権限不足、保存停止、再試行を確認した。実データや実認証器を使った試験とは区別する。
- 新しい画面試験を既存の試験入口から実行する。CI定義・依存manifest/lockfileは変更しない。

変更ファイルだけを対象にGitleaksと手動の差分確認を実施する。Semgrepは承認済みローカルルールがない。依存変更はなく、OSVは適用対象なし。新しいスキルや連携の導入はない。ZAPの実サイトスキャンは許可対象外。リモート連携の内部実装は未検証。

## 残る作業と費用

| 項目 | 次の条件 |
| --- | --- |
| D1本番移行 | 現行の一括保守手順はFreeで許可されないCPU設定を使うため停止中。有料化の承諾前に切り替えない。無料枠を維持する移行には、分割・中断復旧・整合性確認を含む別設計と検証が必要 |
| 保存先の契約確認 | アプリ本体はCloudflare上だが、業務DBはlibSQL。Cloudflare D1の情報から現用DBの契約主体・管理権・保存地域・費用を断定しない |
| 自動バックアップの設定 | 保存先と対象の決定が必要。原本を含むDriveへの送信は具体的な送信先と対象の承諾後に扱う。今回の表示改善でバックアップ取得済みになったわけではない |
| 大容量の追加開発 | 鍵変更の分割、D1初期移行2,000行／16MiB・同期総1,000行／16MiBの枠、案件分割、必要な案件だけの復号、長期履歴設計、Android実機の測定は残る |
| 契約・情報管理票 | 実際の保存先・保持条件と案件別合意を確認して確定する。既存の締結済み文書は上書きしない |

この改善のための有料プラン・新サービス・保存領域の追加は不要。既存の配備経路を使い、アプリの保存先と料金設定は変更しない。既存サービスの利用量による将来の費用をゼロと保証するものではない。

有料化を選ぶ場合の参考：2026-11-10確認の[Workers公式料金](https://developers.cloudflare.com/workers/platform/pricing/)ではPaidは最低月額5米ドル。月1,000万要求・CPU3,000万msを含み、超過は100万要求0.30米ドル・100万CPUms0.02米ドル。税・為替・他サービスは別。D1自体は無料プランでも利用できるため、「D1は必ず有料」とは扱わない。今回、有料化は実行しない。
