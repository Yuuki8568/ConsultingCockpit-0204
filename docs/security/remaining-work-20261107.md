## 本番反映済み：手動の全監査検証（PR #18）

定期的な独立証跡の更新はPR #17で分割済みだったが、手動の全件検証は別処理だった。libSQLでは全暗号化詳細を一括取得し、D1では10,000件／16MiBの全体上限を超えると検証できなかった。

両方式を共通のページ検証に変更した。1回の要求につき最大100件、可変長の全列と行余白を含め約2MiBまで。先に番号・ハッシュ・バイト数だけを読み、本文取得SQLでも上限を再確認する。途中で本文やメタデータが大きくなった場合も、大きな本文を読まず未完了として停止する。

開始時の末尾と独立証跡を固定し、署名した続き情報を本人・ログインセッション・保存方式に結び付ける。続き情報は30分で失効する。通し番号、前ハッシュ、実内容のハッシュ、末尾管理記録、独立証跡を検証し、最後まで一致した場合だけ合格とする。記録の追加・末尾変更があれば最初からやり直す。途中ページを全件合格と表示しない。

画面は確認件数と中止操作に対応する。中止・画面移動・通信失敗後の遅れた応答で成功表示へ戻さず、次のページも要求しない。記録の削除、認証緩和、復号、実データ移行、新しい保存領域の作成は含まない。保存容量表示から、撤廃されたD1の全監査10,000件／16MiB制限を除く。

## 今回の追加改善：端末内保存・復元の照合

通常編集の差分保存と復元の確定前に、元の全レコードを再度 `getAll()` で読み、全体をソート・JSON文字列化して比較していた。このため、呼出し元の元データに加えて全体の複製と大きな比較文字列が同時に存在していた。

比較を同じ読書きトランザクション内のカーソルで1行ずつ進める。IDと全フィールドを照合し、追加・削除・同数差し替え・未編集行の変化も拒否する。全行が一致するまで書込みや全置換の消去を開始しない。通常編集は変更行だけを書き、復元は全置換を原子的に実行する。途中中断・書込エラー時はトランザクション全体を取り消し、元データを保つ。

2,048行／32MiBの合成暗号文で、全件再読込み・全体JSON化を禁止したまま編集と復元が成功。1回の比較文字列の最大は16,493文字だった。実際のChromeのIndexedDBでも別タブの変更拒否、照合中に待機した別接続の書込み順序、復元途中の失敗時の原本保全を確認した。画面・暗号形式・DBスキーマ・認証・保存先・料金プランは変更していない。

これは比較処理の追加メモリ削減であり、金庫全体の段階復号の完成ではない。呼出し元の元データ・復号済み状態・復元後データは引き続きメモリに載り、照合も全行を走査する。1件自体が大きい場合の負担、Android実機の最大件数・使用メモリ・所要時間は未測定。
