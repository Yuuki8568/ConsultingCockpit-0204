## 今回の追加修正：手動の全監査検証

定期的な独立証跡の更新はPR #17で分割済みだったが、手動の全件検証は別処理だった。libSQLでは全暗号化詳細を一括取得し、D1では10,000件／16MiBの全体上限を超えると検証できなかった。

両方式を共通のページ検証に変更する。1回の要求につき最大100件、可変長の全列と行余白を含め約2MiBまで。先に番号・ハッシュ・バイト数だけを読み、本文取得SQLでも上限を再確認する。途中で本文やメタデータが大きくなった場合も、大きな本文を読まず未完了として停止する。

開始時の末尾と独立証跡を固定し、署名した続き情報を本人・ログインセッション・保存方式に結び付ける。続き情報は30分で失効する。通し番号、前ハッシュ、実内容のハッシュ、末尾管理記録、独立証跡を検証し、最後まで一致した場合だけ合格とする。記録の追加・末尾変更があれば最初からやり直す。途中ページを全件合格と表示しない。

画面は確認件数と中止操作に対応する。中止・画面移動・通信失敗後の遅れた応答で成功表示へ戻さず、次のページも要求しない。記録の削除、認証緩和、復号、実データ移行、新しい保存領域の作成は含まない。保存容量表示から、撤廃されたD1の全監査10,000件／16MiB制限を除く。

この追加修正の本番反映状況は対応PRの最新状態で確認する。PR #17で本番反映済みの内容と混同しない。
