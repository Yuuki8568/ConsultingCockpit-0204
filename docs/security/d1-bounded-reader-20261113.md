# 無料枠D1移行：少量読取の工程記録（2026-11-13）

## 完了範囲

`security-ops/d1-bounded-reader.ts` に、元DBを1行ずつ読む内部用の部品を追加した。本番入口・HTTP・cronからは呼ばない。移行先への書込、進捗の永続保存、完了記録の生成、D1への切替は行わない。契約、プラン、認証情報、権限、CI定義、依存関係に変更はない。

これは[無料枠の移行計画](d1-free-plan-20261110.md)の読取部分だけを実装したもの。稼働中の業務DBへの照会はしていない。64KiBは正規化した1行のJSONの上限であり、通信全体のバイト数やFreeのCPU 10msを保証する数値ではない。

## 欠落と無制限の読み込みを防ぐ方法

- 既存スキーマで指定された18表だけを対象とし、列・主キー順・非NULLのTEXT主キー・主キー索引のBINARY昇順を確認する。全スキーマの制約・所有者・外部キーの検証を代替しない。
- 最後に取得した主キーより後の「直後の1行」を、主キー索引で取得する。件数によるOFFSETは使わない。同じカーソルを再試行すれば、変更のない元DBからは同じ行を返す。戻り値を受け取っただけで永続進捗が確定するわけではない。
- SQL内で各値のバイト数と型を確認し、サイズ上限・型の条件を満たす場合だけ本文を返す。大きすぎる行の本文とキーは返さず、固定エラーで停止する。後ろの小さい行へ飛ばして成功扱いにしない。列内分割は今後の課題。
- JSONのエスケープを考慮し、元のバイト数の6倍に固定の余白を加えた保守的な上限を使う。実際には収まる行でも停止する場合がある。SQLの返却はDB側の内部メモリ消費を制限するものではない。
- TEXTはSQLで16進表現にしてから受け取り、厳密なUTF-8復号を行う。ローカルlibSQLドライバーで確認したNUL文字以降の切捨てを防ぎ、BOMを維持し、不正なUTF-8を置換して移さず停止する。BLOBや正確に表せない整数も停止対象。
- 1行ごとに読取トランザクションを閉じる。接続・照会・終了のエラー本文は外へ出さない。戻り値の行とカーソルは非公開情報として扱い、ログ・公開PR・事前検査結果へ載せない。

SQLite公式の[行値比較](https://www.sqlite.org/rowvalue.html)を基に複合主キーでの継続読取を実装し、実際のローカル実行計画で索引検索を確認する。比較の左辺への照合順の指定と、変換後の列別名による並べ替えは索引検索を妨げ得るため、元の主キーを明示し、比較の右辺へBINARYを指定する。

## 検証

`tests/d1-bounded-reader.cjs` は架空のローカルlibSQLのみを使う。既存のD1移行試験入口からも実行する。

- 18表の読取、単一・複合主キーの順序、再試行、末尾判定、重複・取りこぼしのない走査。
- 日本語、絵文字、引用符、NUL、BOMを保持。本文取得前のサイズ停止、次行の飛ばし禁止、壊れた文字コード・未対応型・不正スキーマ・不正カーソルを拒否。
- 実行計画で途中位置からの主キー索引検索を確認。列の既定照合順が異なる場合も、検証済み主キーの順序を維持。
- 接続・照会・確定・終了の失敗に、合成の秘密文字列が出ないことを確認。

この試験は実データ、遠隔libSQL、Workers FreeのCPU、D1移行先への書込を検証していない。実データのための読取部品はまだ運用入口に接続しない。
